# «Тайна»: скрытые записи под замком (15.10.2026)

**Зачем.** Пробные карточки лидов и всё «на подтверждении» (карточки, события, курсы, акции, объявления) не показываются в списках,
но до сих пор лежали в открытых файлах `data/*.js`: любой, кто открывает сайт или скачивает эти файлы (в том числе роботы-сборщики),
видел имена, телефоны, e-mail и тексты приглашений. Режим Ирины `?ira=1` включался без пароля.

**Как устроено.**
- В репозитории всё остаётся как было: `data/*.js` открытые, все скрипты (kartochka.py, zapis.py, klyuch.py, sync.py) работают без изменений.
- Шифруется только копия сайта для посетителей. Её собирает `node _i18n/tajna/zakryt.js --out _site`: каждая запись не «активен»
  (кроме образцов `sample`) заменяется заглушкой `{ tajna: 1, g, w, a, e }`, в начало каждого `data/*.js` вставляется `otkryt.js`.
- Открыть заглушку можно только:
  - **ключом из ссылки письма** (`#preview=<id>.<ключ>`, `#ok=`, `#off=`, `#price=`, `#afisha=`) — лид видит свою карточку и все свои черновики;
  - **ключом владельца** — он появляется на устройстве после пароля: `svoiludi.ch/?ira=1` → окно «Режим владельца». Выйти — `?ira=0`.
- Страница открывает записи сразу, до своего кода, поэтому видит ровно те же данные, что раньше; чужих скрытых записей для неё просто нет.
- Фото скрытых карточек в копии получают случайные имена.
- Шифр: случайный ключ записи; запись — HMAC-SHA-256 в режиме счётчика с подписью; ключ записи запечатан ключом из ссылки и ключом
  владельца (PBKDF2-SHA-256, 310 000 повторов). Один и тот же алгоритм — в `zakryt.js` (Node), `otkryt.js` (браузер) и `tajna.gs` (скрипты Google).

**Файл ключей** `_i18n/tajna/klyuchi.json`: пароль владельца (соль, повторы, ключ) и ключи ссылок `{ id: ключ }`.
- **Пока репозиторий публичный, файла в репозитории нет и быть не должно** (он в `.gitignore`). Он лежит на компьютере Ирины:
  `Coaching - my business\20 Сайт — визитка и блог\Защита сайта (не для сайта)\klyuchi.json`.
- После переезда, когда репозиторий станет закрытым, файл кладём в репозиторий (убрать строку из `.gitignore`). С этого момента
  `klyuch.py`, `kartochka.py` и `zapis.py` сами дописывают в него каждый новый ключ (`klyuch.zapomnit`).
- Запись без ключа в файле открывается только у владельца — `zakryt.js` перечисляет такие записи. Чтобы ссылка письма работала,
  ключ нужно добавить (или сделать новую ссылку: `klyuch.py <id>`).
- Собрать ключи из писем и папок приглашений: `node _i18n/tajna/sobrat.js --klyuchi <файл ключей> <папки или файлы>` — берёт ссылки
  `#preview=…`, `#ok=…` (и `%23preview%3D…` из Gmail), сверяет с keyHash, черновикам лида ставит ключ карточки, в конце называет записи без ключа.
- Новый пароль владельца: `node _i18n/tajna/zakryt.js --novyj-parol "<пароль>"`, потом собрать и выложить сайт.

**Проверки.**
- `zakryt.js` в конце ищет в копии имена, e-mail, телефоны, id и отпечатки ключей скрытых записей — если что-то нашлось, останавливается.
- `node _i18n/tajna/proverka.js --out _site` — открывает каждый `data/*.js` копии как браузер: посетитель без ключа, каждый ключ
  из файла ключей и владелец видят ровно то, что должны; чужой ключ ничего не открывает.

**Скрипты Google.** Подтверждение карточек («Тесты — заявки», версия 6 от 15.10.2026) и записей (`_i18n/podtverzhdenie/zapisi.gs`)
читают данные с сайта и открывают заглушки тем же ключом из ссылки (функции из `tajna.gs`). Открытый вид файлов они тоже понимают.

**Включение (при переезде на Cloudflare).** Показ сайта — из папки `_site`, собранной `zakryt.js`; служебная папка `_i18n` в показ не попадает.
Порядок — документ проекта «pereezd-hosting.md», раздел «Защита при переезде».
